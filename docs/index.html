The safety model

Stop is a moment.
It is not a verdict.

An agent can stop because the work is finished. It can also stop while reporting a failed check, asking a question, or handing back partial work.

DoneThen does not pretend to know the difference. It also does not treat one Hook process as the host's final decision. Without trusted final arbitration, execute stays unavailable and dry-run records only what was observed.

01 / INTENT

The user asks once, inside the original task.

A typed, time-limited arm request records what may happen and explicitly acknowledges that Stop may not mean success.

02 / BINDING

The grant belongs to one session and turn.

The arm Hook binds the job to the current session, turn, and workspace. A Stop-Hook continuation cancels instead of widening the grant.

03 / AUTHORITY

Observation cannot grant power.

The Hook only records lifecycle state. Schedule remains unreachable until a trusted provider can prove the final decision for the exact Stop event and the recovery path is ready.

One task · one lifecycle handoff

No watcher window.
No second Codex run.

The primary integration is a Codex plugin. Codex starts the typed MCP server and narrow lifecycle observers as transport—not as another program the user has to babysit.

What exists today

Implemented without overstating support.

Single-session and multi-session Stop dry-runs are implemented. Platform recognition, backend preflight, and execute readiness are reported separately; no public policy is currently execute-ready.

Read the plugin development guide →

Implemented

  • after_stop and 2-16 target after_all_stop dry-run barriers
  • Session, turn, and workspace binding with continuation cancellation
  • Atomic job state and redacted lifecycle event logs
  • Non-interfering plugin-owned lifecycle observers
  • Supervisor final gate that rejects Stop execution without trusted arbitration
  • Create-once recovery records independent of mutable plugin job JSON
  • Separate experimental verified-success and App Server evidence path
  • Fixed verifier profiles, receipts, cancellation, and reconciliation
  • Windows backend and Linux systemd helper code
  • Capability-bound archives, checksums, provenance, and SPDX SBOMs

Not yet accepted or delivered

  • Real Windows and Linux cancel/power-off release evidence
  • Trusted final Stop arbitration provider and proof lifecycle
  • Verified-success execute and authoritative App Server attachment
  • Published signed release artifacts
  • A signed/notarized macOS power helper
