The safety model

Turn endings are signals.
They are not verdicts.

An agent can stop because the work is finished. It can also stop while waiting for approval, reporting a failed test, asking a question, or handing back partial work.

DoneThen keeps those states separate. Unknown, malformed, interrupted, partial, blocked, approval-waiting, and failed outcomes all resolve to the same safe decision: do nothing.

01 / INTENT

The user asks once, inside the original task.

A typed, time-limited arm request records what may happen. The model cannot invent a post-task command or silently widen that authority.

02 / EVIDENCE

Completion is structured, bound, and invalidatable.

The Skill and Hooks bind evidence to the same session and turn. A later prompt invalidates stale READY evidence instead of reusing it.

03 / AUTHORITY

The final decision lives outside the Hook.

Stop and SessionEnd remain observations. A narrow external supervisor must pass every gate before a cancellable action can exist.

One task · one evidence chain

No watcher window.
No second Codex run.

The primary integration is a Codex plugin. Codex starts the typed MCP server and narrow lifecycle observers as transport—not as another program the user has to babysit.

What exists today

Implemented without overstating support.

The public plugin exposes dry-run only. Policy capture cannot enable the destructive path until an authoritative same-host attachment and real platform evidence exist.

Read the plugin development guide →

Implemented

  • Typed arm, finish, pause, cancel, and status
  • Task and turn binding with stale-evidence invalidation
  • Atomic job state and redacted lifecycle event logs
  • Non-interfering plugin-owned lifecycle observers
  • Detached one-shot supervisor with monitored, cancellable countdown
  • App Server evidence adapter with fail-closed host ownership checks
  • Fixed verifier profiles, receipts, cancellation, and reconciliation
  • Windows backend and Linux systemd helper code
  • Capability-bound archives, checksums, provenance, and SPDX SBOMs

Deliberately unavailable

  • Supported power actions from the plugin workflow
  • Stable authoritative attachment to the current Codex host
  • Real cancel, power-off, and post-boot acceptance evidence
  • Signed Windows and signed/notarized macOS releases
